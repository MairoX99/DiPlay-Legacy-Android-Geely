# DiPlay Geely E01 — v0.3.5-geely-rc

吉利星瑞 E01（ECARX E01 / MediaTek MT6735 / GKUI 19，**Android 5.1 / API 22**）的 CarPlay 车机端口。

基于 `programmerguohuajing/DiPlay-Legacy-Android` **v0.2.7**，从上游 `shihabal3amri/DiPlay`
选择性移植品牌无关的改进。**本版未重新核对上游**：锚点仍是 `main` `5e58b4b`（2026-10-07），
上游标签 **v0.2.13**，上一版面向上游的移植结论对本版继续成立。

---

## 有线：超时刚好读到的包留下，NCM 出方向坏了要报

API 22 上 USB 读超时靠定时器取消请求。取消和“包刚好传完”会撞在一起。有线 iAP2 不开确认，
这个包丢掉，整条 USBMUX 就断。本版只在截止点到了、缓冲区仍是空的时候才当超时；缓冲区里已经有
字节就留下。NCM 读仍走不带超时的等待，超时后请求继续留在队列里。

NCM 出方向：手机还没发过帧时，bulk OUT 失败仍当成会话前的 NAK，记一次然后重试。手机已经发过
帧之后，连续失败计到 3 次就结束会话，和 USBMUX 写失败同一类处理。这 3 次里**不再**发
`CLEAR_FEATURE(ENDPOINT_HALT)`。那条控制传输在端点并没停住时也会把数据切换位复位成 DATA0，
而且它不是内核的清 halt，一次普通 NAK 可能被做成三次失败再整段重连。真正的 halt 仍由重新打开
设备清掉。

**这两处都还没在车上验证。**

## 无线入口重新打开

E01（FS11GQJ）不再被整段藏起无线。上次用的是无线还是 USB，按存下来的值读，默认是无线。
厂方顾凯蓝牙仍完不成 iAP2 的 RFCOMM，这一版没有改那条路。有线 USB 仍是这台车上唯一跑通过的路径。

## 默认连接只用于自动连接

设置里可以选上次使用、无线或 USB。只在 DiPlay 自己打开、而且打开了“启动时连接”时生效。
手动点的按钮仍走你点的那种。自动连接默认关，也只在第一次进入、没有设置错误、没有后台会话、
意图里没有指定页面时跑一次。

## 首页写这台设备能调用哪些连接

- USB：有 USB Host。
- 车载热点：Wi-Fi 服务、热点开关 `setWifiApEnabled`、蓝牙适配器、读蓝牙状态、
  `createRfcommSocketToServiceRecord` 都能调到，并且蓝牙是开的。
- Wi-Fi Direct：只在 Android 10 及以上。这台车机不会出现。

某一步调不起来，车载热点就不写进“可以用”，首页、连接设置、会话里的 Wi-Fi 设置都会写出原因。
蓝牙只是关着，或者还没给蓝牙权限，设置页留下，并说明要先打开或先授权。检测不会打开蓝牙或热点，
也不会去连 socket。

这台车机上，AOSP 蓝牙经常是关的，厂方蓝牙开着不算。那种情况下首页会是“可以用 USB”，并写
“当前蓝牙是关的”；无线设置页仍在。**还没在车上看过这行字。**

首页大按钮在无线还能调时仍直接开始无线，不跟着“默认连接”走。连接设置里若只剩车载热点，
仍要先点一次再填热点。这两处本版没改。

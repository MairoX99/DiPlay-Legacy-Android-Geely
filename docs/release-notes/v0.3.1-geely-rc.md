# DiPlay Geely E01 — v0.3.1-geely-rc

吉利星瑞 E01（ECARX E01 / MediaTek MT6735 / GKUI 19，**Android 5.1 / API 22**）的 CarPlay 车机端口。

基于 `programmerguohuajing/DiPlay-Legacy-Android` **v0.2.7**，从上游 `shihabal3amri/DiPlay`
选择性移植品牌无关的改进。**本版对照上游 v0.2.13 复核过。**

---

## 本版新增（相对 v0.3.0-geely-rc）

### 修复：没有 NSD 服务的车机上，无线 CarPlay 起不来

Bonjour 广播在**构造时**就去取 Android 的 NSD 服务。但本 fork 走的是**绑定网卡的 mDNS**
（`CarPlayController` 里写死 `useInterfaceMdns = true`），**根本不用 NSD** ——
那次查询纯属多余，却会让整条无线链路在开始之前就失败。

上游在 `32550b2` 修掉了它，注释写得很清楚：

> Interface-bound mDNS does not need Android's NSD service,
> **which may be absent on some head units.**

改为延迟查询 + 空值兜底。**E01 上是否真的缺 NSD 未验证** —— 这条是消除一整类失败的可能，
不是确认本车中过这个招。

### 构建

- **`gradlew` 补上可执行位。** 此前 CI 里 `./gradlew` 一律 `Permission denied`，
  `Android checks` 每次推送都是红的；本地走 `sh gradlew` 所以一直没暴露。
- **发布自动化。** 推 `main` 时由 `mobile/build.gradle.kts` 的 `versionName` 自动推导 tag
  并发布本包，tag 不再手敲；该版本已有 Release 就跳过。发布前强制过四道门：
  tag 与 versionName 一致、release notes 存在、源码树无凭据、包验过 v1/v2 签名且带
  `assets/offline-mfi/` 身份。

## 安装

⚠️ **签名与官方 DiPlay APK 不同，无法覆盖安装。** 需先卸载：

```sh
adb uninstall com.shihab.diplay
adb install -r DiPlay-Legacy-Geely-V031.apk
```

卸载会丢失应用内设置（分辨率、音频缓冲、方向盘按键角色、已存 Wi-Fi 凭据）。
无 adb 时可直接拷 U 盘，用车机文件管理器安装（需允许「未知来源」）。

## 与官方上游的关系

**本版不等于官方 DiPlay。** `-geely-rc` 表示「Geely 线自己的候选版」。

本版对照的是上游 **v0.2.13**（较本 fork 的基线 v0.2.7 领先 **483 个 commit**）。
那 483 个里对 E01 有意义的已基本取尽；本次新缺口只有 19 个 commit，其中只有上面那条 NSD
修复可移植。其余要么是**无硬件可对齐**（DiLink 3/4/5 仪表集群、BYD HUD、CAN 电池），
要么是**平台够不着**（Wi-Fi Direct / P2P 需 API 29，E01 是 API 22），
要么已明确**不做**（缓冲音频 `BufferedAudioStream` —— 拿内存换抗卡顿，
而本车 `MemFree` 常态只有 26–33 MB，上游自己也默认关闭）。

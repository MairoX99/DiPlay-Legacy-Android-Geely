# DiPlay Geely E01 — v0.3.2-geely-rc

吉利星瑞 E01（ECARX E01 / MediaTek MT6735 / GKUI 19，**Android 5.1 / API 22**）的 CarPlay 车机端口。

基于 `programmerguohuajing/DiPlay-Legacy-Android` **v0.2.7**，从上游 `shihabal3amri/DiPlay`
选择性移植品牌无关的改进。**本版对照上游 `main` `e2fd8ea` 复核过。**

> 上一版实际发布的是 **v0.3.0-geely-rc**。`v0.3.1-geely-rc` 只改了版本号和文档、没发出来，
> 它的内容（NSD 修复、发布自动化）已包含在本版里。

---

## 头条：本车蓝牙无法支撑无线 CarPlay，UI 已不再提供

**E01 上不要再用无线 CarPlay —— 不是没做好，是这台车机的蓝牙栈不给通道。**

无线 CarPlay 的 iAP2 那一段走的是蓝牙 RFCOMM socket。这台车机的蓝牙栈**不向三方应用开放
任何 socket**，而且是**有意为之**，三处互相独立的删减指向同一个结论：

| 层 | 位置 | SPP / RFCOMM |
|---|---|---|
| ① AOSP 栈改造版 | `XCBTService`（运行中，adapter `STATE_ON`，5 个服务全 exported 无权限） | ❌ socket 类被整个删除 —— `createRfcommSocketToServiceRecord` / `listenUsingRfcommWithServiceRecord` / `fetchRemoteUuids` 全无，而 `getBondedDevices` / `startDiscovery` 都在 |
| ② ECARX 门面 | `com.ecarx.xui.adaptapi.bt.*`（在 boot classpath） | ❌ 声明了 `bt/spp/ISpp` + `ISppCallback`，**没写 `SppProxy`** |
| ③ GOC SDK | `com.nforetek.bt`（`CommandSppImp`） | ❌ 每个方法硬编码 `return false` |
| ④ GOC daemon | `/system/bin/gocsdk` | ✅ 有完整 SPP，但命令表 **119 条**里没有 SDP 查询 / 自定义 UUID / 裸 RFCOMM，够不着 iPhone 的 iAP2 服务；iOS 也不向非 MFi 配件开标准 SPP |

实机印证：绑上 `NfServiceSpp` 后 `isSppServiceReady() = 0`，对已配对的 iPhone 调
`reqSppConnect(...)` 返回 **`false`**。厂商 dex 里没有任何 iAP / Apple / CarPlay 类，
车机上 `pm list packages` 过滤 `apple|carplay|airplay|iap` **零命中**。

**⚠️ 蓝牙本身没问题。** 免提通话、蓝牙音乐照常工作，三方应用也能读适配器状态、当前连接的
设备和本机 MAC。**缺的只是「在蓝牙上开一条字节通道」，而这台车机上唯一需要它的就是无线
CarPlay。** 所以：

- 主页、连接设置页、会话内设置菜单**只保留 USB**，无线开关与热点控件不再出现
- `AirPlayPersistence.loadWirelessEnabled` 在 E01 上**硬钳到 `false`** —— 老版本存下的
  `true` 也压不住它，不会去起一个硬件做不完的连接
- 连接设置页会直接说明原因，不再让人找不到入口
- **其它车机不受影响** —— 单 APK、无 flavor，无线开关在蓝牙栈支持的机器上照常显示
- **有线 USB CarPlay 不受影响**，仍是本车唯一受支持的路径

## 本版新增（相对 v0.3.1-geely-rc 的内容，基线为已发布的 v0.3.0-geely-rc）

### E01 专属

- **导航播报落到了 FM 上，已修。** 本 fork 原本把导航流默认值定在 14（比亚迪的驾驶位扬声器流）。
  E01 把厂商流类型**重新编号**了：这里 14 是 `STREAM_FM`（收音机），播报该走 `STREAM_NAVI_TTS`
  = **10**（本车自己的 `AudioManager` 就是这么声明的）。默认值现在按车机选。
  ⚠️ **老装机注意** —— 偏好里已存过值的不会被这次改动覆盖（`getInt` 只在键不存在时才用默认值），
  升级后请在设置里**重新选一次**导航流类型。
- **无线入口按上面的结论收拢**（见头条）。

### 从上游移植（对照 `main` `e2fd8ea`，v0.2.13 之后 51 个 commit，取 4 个）

- **通话时音乐让路。** 瞬时失焦把媒体轨增益设 0，闪避设 0.2，恢复设 1；电话与导航轨不动，
  永久失焦不改增益。仍用 API 8 的请求方式，因为 `AudioFocusRequest` 是 API 26。
- **RFCOMM 改为上报「流缺失 / 卡住」**，不再在平台 getter 里失败；双工流自己持有已连接的
  socket，失败的 getter 不会留下第二个持有者。**未在实车验证。**
- **USBMUX 四字节 trailer** 在已捕获的 protocol-1 诊断帧之前现在也被接受（原先只处理 TCP 回复）。
- **视频接收日志加入解密耗时**（`decryptAvgUs` / `decryptMaxUs` / `decryptMBps`）。

### 未移植（本区间内明确不做）

计划任务式昼夜模式、可指派 Siri 方向盘键、自定义图片选择器、软件视频窗口、
USB 读队列回退（针对 API 26），以及繁体中文与上游站点内容。

- **本版的 UI 改动** —— 逻辑与编译已验证；「E01 上打开确实只剩 USB」需装到车上跑一次
- **本版的导航流修复** —— 需在车上确认播报走的是 10 而不是 14

- **USB 权限自动确认** —— 需无障碍服务；GKUI 没有「无障碍」设置入口，目前只能靠 ADB 开启
- **诊断导出回退**（无文件选择器的车机）、**音频卡顿诊断时间线**

### 构建验证

- **v1(JAR) 签名有效** —— API 19 的老车机只认 v1；v2 亦有效

## 安装

⚠️ **签名与官方 DiPlay APK 不同，无法覆盖安装。** 需先卸载：

```sh
adb uninstall com.shihab.diplay
adb install -r DiPlay-Legacy-Geely-V032.apk
```

卸载会丢失应用内设置（分辨率、音频缓冲、导航流类型、方向盘按键角色、已存 Wi-Fi 凭据）。
无 adb 时可直接拷 U 盘，用车机文件管理器安装（需允许「未知来源」）。

> 若从 **v0.3.1 之前**的版本升上来且离不开无线 —— 没有这个选项，本车从来就没有过。

## 与官方上游的关系

**本版不等于官方 DiPlay。** `-geely-rc` 表示「Geely 线自己的候选版」。

官方近几个版本的头条功能**几乎全部依赖比亚迪 DiLink**，吉利 E01 上无对应硬件或平台不可行，
本版**均未包含**：中控悬浮地图、仪表盘显示 CarPlay 歌曲、launcher 导航 widget、
Android 11+ launcher 内嵌地图、BYD 昼夜模式、环视续连。

**Wi-Fi Direct** 相关为 **API 29+** 能力，E01 是 API 22，平台够不着。
**缓冲音频**不做 —— 拿内存换抗卡顿，而本车 `MemFree` 常态只有 **26–33 MB**。
**Same LAN（现有 Wi-Fi）** 经复查在本车可行（只需三处 API 垫片），**尚未移植**，
但它和无线 CarPlay 无关：那只解决「iPhone 和车机同网」的发现，替代不了蓝牙上那一段 iAP2。

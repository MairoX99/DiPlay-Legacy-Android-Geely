# DiPlay Geely E01 — v0.3.3-geely-rc

吉利星瑞 E01（ECARX E01 / MediaTek MT6735 / GKUI 19，**Android 5.1 / API 22**）的 CarPlay 车机端口。

基于 `programmerguohuajing/DiPlay-Legacy-Android` **v0.2.7**，从上游 `shihabal3amri/DiPlay`
选择性移植品牌无关的改进。**本版对照上游 `main` `5e58b4b`（2026-10-07）复核过。**
该点在上次锚点 `e2fd8ea` 之后还有 **19** 个非合并提交，上游标签仍是 **v0.2.13**。
这 19 个都没有迁入。

## 头条：播放时少写日志、少分配

有线播放时，应用自己把帧间隔拉长了。上一轮实车抓包是大约 35 fps 进来、中位大约 23 fps 出去。
热路径上每包都在做这些事：有线 carkit 每次发送逐包记 TX/RX 并切成 256 字节，USBMUX 每帧记一条，
iAP2 成功帧再走一遍 TLV 格式化。这些文本本来就不会落盘——`DiagnosticRedactor` 对含
`TRACE ` / `PHONE ` / 换行的行直接丢掉，而格式化结果是多行的。本版把这三处从热路径拿掉。
连接建立、失败和断开的日志还在。

剩下的会话日志改到单线程 `diplay-session-log` 上写，`SimpleDateFormat` 只留一个，文件长度在内存里记账。
长度和写锁按路径共享：画面重建时，上一段还在排空的 writer 不能按过期长度把新日志转走。

音频复用收包缓冲、AAD、nonce、明文和同一个 ChaCha20-Poly1305。视频复用 128 字节帧头，帧体缓冲涨到
1 MiB 为止，再大就这一帧单独分配，流关闭时放开。交给解码队列的 RTP，以及 `decryptFrame` 的返回值，
仍是新数组：解码线程异步持有，下一包不能覆盖还在解的帧。配对用的一次性加解密不变。
平台 ChaCha 仍不迁——API 28 才有，这台车机上只会退回现有的 BouncyCastle。

帧间隔和 GC 还没在车上量过。编这个版本时车机没有 adb。

## 上游这 19 个提交，本版不迁

### 设置页改成左侧导航栏

祖父把设置收成分类，加了导航栏、翻译、没用到的文案清理，以及随后对滚动位置、热点就绪和
仪表投屏确认框的修补。这些页面围着比亚迪的车辆、仪表、昼夜和方向盘学习。本分支的设置页
已经是另一套吉利布局，整页搬过来对不上。

### 实验性 Smooth video

默认关闭。它把每一帧按 iPhone 的时间戳再推迟显示，延迟在 30–200 ms，30 fps 时起步大约 140 ms。
测量是在比亚迪唐上做的：高通 `c2.qti.avc.decoder`、2560×1440、60 fps，解码器会攒着大约两帧才吐。
为这条路径配套的离屏挂起解码器、以及销毁 Surface 前在主线程上等待卸下，也只服务这个实验项。

这台 E01 是联发科 MT6735、1920×720。已经量到的问题是应用把帧送出去比收到更慢，再把每帧多按住
一百多毫秒，只会让触摸更晚，不会把吞吐补上。带时间戳的 `releaseOutputBuffer` 还是 API 21，
低于本分支的 API 19 底线。

## 安装

⚠️ **签名与官方 DiPlay APK 不同，无法覆盖安装。** 从本分支的上一版升上来可以覆盖，签名相同：

```sh
adb install -r DiPlay-Legacy-Geely-V033.apk
```

若车上是官方包，需先 `adb uninstall com.shihab.diplay`。卸载会丢失应用内设置。
无 adb 时可直接拷 U 盘，用车机文件管理器安装（需允许「未知来源」）。

同版本的 debug 包名是 `com.shihab.diplay.hudtest`，不能覆盖正式包。

## 与官方上游的关系

**本版不等于官方 DiPlay。** `-geely-rc` 表示「Geely 线自己的候选版」。

官方近几个版本的头条功能几乎全部依赖比亚迪 DiLink，或者要 API 29 的 Wi-Fi Direct。
本版对照 `5e58b4b` 之后，仍不包含：设置导航栏、Smooth video、仪表投屏、缓冲音频。
**有线 USB CarPlay 仍是这台车唯一受支持的路径。**

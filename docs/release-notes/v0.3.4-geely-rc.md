# DiPlay Geely E01 — v0.3.4-geely-rc

吉利星瑞 E01（ECARX E01 / MediaTek MT6735 / GKUI 19，**Android 5.1 / API 22**）的 CarPlay 车机端口。

基于 `programmerguohuajing/DiPlay-Legacy-Android` **v0.2.7**，从上游 `shihabal3amri/DiPlay`
选择性移植品牌无关的改进。**本版未重新核对上游**：锚点仍是上次的 `main` `5e58b4b`（2026-10-07），
上游标签 **v0.2.13**，上一版面向上游的移植结论对本版继续成立。

## 头条：修掉 API 22 上失效的 USB 读超时

`UsbApiCompat.waitForUsbRequest` 在 API < 26 上走的是不带超时的 `requestWait()`。这台车机是
API 22，于是 `Iap2UsbSession.read(timeoutMillis)` 的超时被整个丢掉：手机不回 USBMUX 版本应答时，
`Iap2UsbMuxHost.begin()` 会一直挂着，而不是 60 秒后报超时。

本版新增 `awaitUsbRequest`：API 26+ 仍用带超时的重载（行为不变），以下用定时器在截止点取消该
请求——正是 `Iap2UsbSession.close` 已经在用的跨线程唤醒，不是新机制。NCM 的 `readChunk` 依赖
"超时后请求仍留在队列里"，与这条路径的假设相反，维持原样。

线索来自兄弟仓库 `xikai6282/DiPlay-Geely-Android43` 的 API18 适配补丁。**尚未在车上验证。**

## 设置里加了"重启应用"

设置页底部、退出上面。走 `exitApplication` 同一套收摊（controller / sink / 后台会话 /
`DiPlaySessionService` 全清），但**不杀进程**，然后用清任务的方式重新拉起 launcher。进程活着，
所以 VPN 权限不会重新要。

两点取舍：重启后落在 **launcher 首页**，不是回到 CarPlay 屏；未应用的设置改动会和"退出"一样被丢弃。
故意不先 `finish()` —— Activity 退到后台之后再 `startActivity` 会被新版系统拒绝，按钮会点了没反应。

## 连接界面显示握手步骤与 USB 总线

有线握手卡在哪一步以前只能看 logcat。连接界面现在常驻两块：每 2 秒刷新的 USB 总线列表
（`UsbBusFormat`），和打时间戳、上限 24 行的握手步骤（`HandshakeLog`）。两者都从既有 `debugLog`
分流，PHONE / TRACE 行仍不进画面。

同时补细了重新枚举这条路径的日志：`IphoneUsbHost` 的 `0x52` 失败带上 vid/pid/class 与 config
列表，`CarPlayController` 记下 config 有无和第几次 reenum。另有手动重连按钮。

## 有线会话不再抓手机的 syslog

配对后打开的 `com.apple.syslog_relay` 和 iAP2 控制共用同一条 USBMUX 管道、同一条读线程，读满
2 分钟。它看不到 `0x52`（那发生在它之前），PHONE 行也不再进画面，本版单独删掉。

## 安装

⚠️ **签名与官方 DiPlay APK 不同，无法覆盖安装。** 从本分支的上一版升上来可以覆盖，签名相同：

```sh
adb install -r DiPlay-Legacy-Geely-V034.apk
```

若车上是官方包，需先 `adb uninstall com.shihab.diplay`。卸载会丢失应用内设置。
无 adb 时可直接拷 U 盘，用车机文件管理器安装（需允许「未知来源」）。

同版本的 debug 包名是 `com.shihab.diplay.hudtest`，不能覆盖正式包。

## 与官方上游的关系

**本版不等于官方 DiPlay。** `-geely-rc` 表示「Geely 线自己的候选版」。

官方近几个版本的头条功能几乎全部依赖比亚迪 DiLink，或者要 API 29 的 Wi-Fi Direct。
本版仍不包含：设置导航栏、Smooth video、仪表投屏、缓冲音频。
**有线 USB CarPlay 仍是这台车唯一受支持的路径。**
